# Pre-Registration PR-2026-02 — E3-A: EEG Grasp Onset Anticipation

**Status:** Draft — pending sign-off from both team members
**Track:** A
**Experiment:** E3-A (Track A Operating Manual S5.3)
**Date opened:** 2026-08-23

## 1. Hypothesis

**H2 (manual S1.2):** a decodable fraction of EEG grasp/intent information
is available before EMG onset, at usable lead times and false-positive
rates.

Using MRCP-band (0.3-3 Hz) features extracted in sliding windows before
EMG threshold-marked onset, on WAY-EEG-GAL's uniform grasp task, we
expect at least one detector family (sLDA baseline or EEGNet) to show a
positive, non-zero mean detection lead time for at least a subset of
subjects, at true-positive rates and false-positives-per-minute jointly
better than the shuffled-onset null's floor.

**We are indifferent between confirming and disconfirming this
hypothesis** (S0.4). Per the manual S5.3 and the source protocol doc:
"Detection only achievable at unusable false-positive rates" is a
valid, reportable, publishable outcome — the operating curve is the
deliverable either way. E3-A is complete when the curve exists with
per-subject spread, CIs, and a passing surrogate panel — **not** when
a usable operating point is found.

**Refutation condition (on the hypothesis):** no detector family, on
any subject, produces a mean lead time reliably distinguishable (per
the shuffled-onset permutation test, Holm-corrected across operating
points) from the null at any FP/min the field would consider usable.

**Failure condition (on the project):** the pipeline cannot produce a
passing surrogate panel at all (time-reversed or shuffled-onset control
fails to collapse as expected) — this indicates a pipeline defect (cue
leakage, baseline drift, onset misalignment; see S6 below), not a
scientific answer, and blocks any interpretation of the curve until
fixed.

## 2. Source

E3-A protocol doc, "EEG Grasp Onset Anticipation (E3-A) — Experiment
Protocol" (Project Regenesis, Track A), as elaborated in Track A
Operating Manual S5.3. No external published target number is being
reproduced here — E3-A is an original measurement on our data, not a
reproduction (unlike PR-2026-01/T1-R). Lew et al.'s anticipatory
movement-intent detection work (manual S: Evidence Table) informs what
lead times and false-positive costs are plausible a priori, but is not
a pass/fail tolerance band the way Wang et al. (2023) was for T1-R.

## 3. Dataset

**WAY-EEG-GAL** (Luciw, Jarocka & Edin, *Scientific Data* 2014,
doi:10.1038/sdata.2014.47; corpus doi:10.6084/m9.figshare.988376). Per
the protocol doc: "Only available dataset with synchronized EEG and
EMG." Grasp task is uniform (single grip type, varying weight/friction)
— results are scoped to this grasp only, not grasp type in general
(S6.1's common mistake #1: this dataset does not support grasp-*type*
diversity claims).

**Status of the loader as of this pre-registration:** `data/way_eeg_gal.py`
exists but its internal MATLAB struct field-name assumptions have
**not yet been confirmed against a real downloaded corpus file** — see
that file's module docstring. Per manual S6 ("no dataset enters this
project on the strength of a description"), this pre-registration is
signed with that verification step as an explicit open item (S8, item
1) — **no result may be reported under this PR until it is closed.**

## 4. Pipeline (per protocol doc, manual S5.3)

1. Load WAY-EEG-GAL via `data/way_eeg_gal.py`; record dataset version
   hash (`compute_dataset_hash`). Measure the actual EEG/EMG timing gap
   per series (`measure_sync_gap`) — never assumed.
2. Mark true movement onset from EMG via threshold-crossing
   (`eeg/anticipation.emg_threshold_onset`). Hand-verify onset detection
   on at least 30 trials before proceeding (protocol doc; logged as
   `n_hand_verified_trials` per `experiments/logging_e3a.py`).
3. Extract MRCP features (0.3-3 Hz) in sliding windows preceding onset
   (`preprocessing/features_eeg.py`).
4. Clean the signal: surface Laplacian (`preprocessing/eeg_filters.surface_laplacian`)
   plus rejection of trials with amplitude spikes or abnormal statistics
   (`preprocessing/eeg_artifacts.reject_trials`). No ICA (deliberate —
   see `eeg_artifacts.py`'s module docstring).
5. Run detectors: sLDA background baseline
   (`eeg/anticipation.build_slda`, on hand-crafted mean/slope window
   features) and EEGNet main model (`eeg/decoder_eegnet.py`, on raw
   windowed signal), equal tuning budgets, nested inner-fold
   hyperparameter selection.
6. Sweep the detection threshold (`eeg/anticipation.threshold_sweep`);
   at each threshold compute mean detection lead time, TPR, FP/min.
7. Report per-subject curves with bootstrap CIs
   (`eeg/anticipation.per_subject_curve_with_ci`, via `eval/stats.py`).

## 5. Controls (all three mandatory, protocol doc)

- **Time-reversed surrogate** (`eeg/anticipation.time_reversed_surrogate`,
  via `eval/surrogates.time_reversal`) — a real pre-movement signal
  should not survive being played backwards.
- **Shuffled-onset null** (`eeg/anticipation.shuffled_onset_null`) —
  randomize onset times within the recording; detection should collapse
  to the false-positive floor. **Deviation, stated up front:** this
  surrogate is not yet available in `eval/surrogates.py`
  (S0.1: splitters/surrogates/metrics come from `eval/` only). A local
  implementation is used per that file's docstring, with an issue to be
  filed against `eval/` requesting Track E adopt it; the local copy is
  to be deleted in favor of `eval/`'s version once it lands, and this
  is flagged as an open item at code review (S8, item 2).
- **Pre-baseline-shift check** (`eeg/anticipation.pre_baseline_shift_check`)
  — baseline correction over a window excluding the pre-onset period,
  to rule out slow baseline drift masquerading as MRCP.

## 6. What a wrong result looks like (protocol doc Failure Modes)

- **Leads cluster near the cue-to-onset interval** → detector may be
  picking up the cue rather than the movement. Verify cue timing is not
  inside the feature window before trusting any positive result.
- **Effect survives time reversal** → likely baseline drift
  masquerading as MRCP. Recover via the pre-baseline-shift check; do not
  report the effect as anticipation until this is resolved.
- **Onset leads implausibly long** → onset labels likely misaligned.
  Recover by hand-verifying trials again (step 2) before re-running the
  sweep.
- **A single operating point reported instead of a full curve** → not a
  completed E3-A result under this PR; re-run the threshold sweep.
- **Uniform near-ceiling TPR at near-zero FP/min across all subjects and
  all thresholds** → suspect leakage (S0.6) before celebrating — check
  that windowing truly excludes post-onset samples
  (`preprocessing/features_eeg.sliding_windows` drops any window whose
  right edge falls at or after onset) and that the EEG/EMG clocks were
  correctly aligned via the measured sync gap, not assumed.
